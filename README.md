# Strata LLM Console

A local control plane for Strata-based LLM serving. It combines a model catalog, an OpenAI-compatible gateway, configuration analysis, request tracing, safe LAN exposure, Telegram control, and multilingual UI.

## Engine origin

Strata LLM Console is a control and orchestration layer built around the **Strata inference engine**:

- Official engine repository: [Niko1221/Strata](https://github.com/Niko1221/Strata)
- Upstream source: `https://github.com/Niko1221/Strata.git`
- The console keeps its own catalog/configuration layer so engine updates can be checked, merged and reverted independently.
- Model packs, GGUF files and engine artifacts are intentionally kept outside this repository.

The repository is designed to keep engine/model artifacts outside Git. Runtime state, tokens, traces, logs, GGUF files and packs are ignored.

## Product areas

- **Operate** — select, stop, unload, remove and register models; edit parameters; optimize a target context.
- **Observe** — live GPU/RAM metrics, historical performance, request traces, exposed reasoning, responses and errors.
- **Connect** — localhost/LAN exposure, Bearer authentication, CORS and encrypted tunnel controls.
- **System** — Strata version/update flow, backend detection and browser preferences.

## API

The gateway is OpenAI-compatible:

```text
http://127.0.0.1:8090/v1
```

The control API is local by default and uses `X-Strata-Token` or `Authorization: Bearer $STRATA_CONSOLE_TOKEN`.

Important endpoints:

- `GET /health`
- `GET /v1/models`
- `POST /v1/chat/completions`
- `POST /v1/responses`
- `POST /v1/messages`
- `POST /v1/embeddings`
- `GET /api/status`
- `GET /api/traces`
- `GET /api/connection`
- `GET /api/backends`
- `GET /api/optimize?context=200000&profile=balanced&model=<id>`
- `POST /api/add`
- `POST /api/remove`
- `POST /api/config`
- `POST /api/select`
- `POST /api/update`

Remote clients require a Bearer token. LAN mode and CORS are opt-in.

## Model lifecycle

Removing a model removes only its catalog/config entry and any unit generated by the console. GGUF files and packs are never deleted automatically.

The update flow fetches and merges the official Strata repository only after an explicit operator action. Installation and package hooks never clone the engine or execute upstream code. If the checkout is missing, use **System → Update** or `strata-console update`; the operation runs under the console service user and reports every change.

## Measured configuration evaluation

The Optimizer can launch a bounded evaluation job for the selected model. During the evaluation, normal inference is locked and returns `423 EVALUATION_IN_PROGRESS`; the evaluator owns the model so user traffic cannot contaminate the measurements.

Each candidate is tested with:

- A short prompt for low-context responsiveness.
- A long deterministic prompt for context pressure.
- Configurable repetitions per prompt.
- One warm-up request kept separate from scored samples.

The result reports success/error rate, latency p50/p95/mean/stdev, decode tokens per second, long/short throughput ratio, stability variance, warm-up cost, risks, estimated memory and a composite score with separate speed, reliability and stability components.

The user can inspect every candidate and apply one measured configuration. Applying creates a pre-evaluation backup, updates the model configuration and restarts the model before returning control.

API flow:

```text
POST /api/evaluations
GET  /api/evaluations/<job_id>
POST /api/evaluations/<job_id>/apply
```

Example request:

```json
{
  "model": "qwen-iq3-s",
  "context": 200000,
  "profile": "balanced",
  "runs": 3,
  "long_prompt_chars": 120000
}
```

The result is measured evidence for this machine and model, not a universal benchmark. Repeat it after hardware, engine or model changes.

## Telegram control bot

`telegram_control_bot.py` provides an allowlisted inline control center for:

- status and models;
- model selection, stop and catalog removal with confirmation;
- traces and errors;
- optimizer and connection status;
- backend detection and Strata updates.

It supports English, Spanish, Portuguese, French and German. English is the default for new chats. Configure the token only in a local environment file:

```bash
cp telegram-control.env.example telegram-control.env
chmod 600 telegram-control.env
# edit TELEGRAM_STRATA_BOT_TOKEN and TELEGRAM_STRATA_ADMIN_IDS
```

The service example is `telegram-control.service.example`.

## Linux installation

The first distribution target is Linux. The installer is user-scoped, does not require root, verifies SHA-256 before replacing the previous version, installs into `~/.local/share/strata-llm-console`, creates `~/.local/bin/strata-console` for the operator CLI and keeps `strata-llm-console` as the server wrapper. A systemd user service is registered when available.

After a release is published:

```bash
curl -fsSL https://github.com/monrroyag/strata-llm-console/releases/latest/download/install-linux.sh \
  | bash
```

The installer supports an explicit version and custom locations:

```bash
curl -fsSL https://github.com/monrroyag/strata-llm-console/releases/latest/download/install-linux.sh \
  | bash -s -- v0.1.0
STRATA_CONSOLE_HOME="$HOME/.local/share/strata-console-test" \
  bash install-linux.sh v0.1.0
```

The Debian package installs a systemd template for model units and a narrow root-owned helper authorized only through `sudoers` for `start/restart/stop/enable/disable` of validated `strata-console-model@<id>.service` names. The HTTP server never writes `/etc/systemd/system`, and both the console and model units run as `strata-console`. The package wrappers export `STRATA_CONSOLE_STATE_DIR=/var/lib/strata-llm-console` and `STRATA_CONSOLE_TOKEN_FILE=/var/lib/strata-llm-console/token`, so the installed CLI uses the same authenticated state as the service. The tunnel uses the console token as its single external authentication boundary; it does not generate or persist a second model key. Strata engine binaries, GGUF files and model packs stay outside the release artifact. The default panel is `http://127.0.0.1:8090`.

### Debian/Ubuntu quick install

Each tagged release also includes a native `.deb` package. It installs the console under `/opt/strata-llm-console`, keeps runtime state under `/var/lib/strata-llm-console`, creates a hardened system service and preserves state across package upgrades:

```bash
VERSION=v0.3.7
curl -fL -o /tmp/strata-llm-console.deb \
  "https://github.com/monrroyag/strata-llm-console/releases/download/${VERSION}/strata-llm-console-${VERSION#v}_amd64.deb"
curl -fL -o /tmp/strata-llm-console.deb.sha256 \
  "https://github.com/monrroyag/strata-llm-console/releases/download/${VERSION}/strata-llm-console-${VERSION#v}_amd64.deb.sha256"
(cd /tmp && sha256sum -c strata-llm-console.deb.sha256)
sudo apt install /tmp/strata-llm-console.deb
sudo systemctl status strata-llm-console --no-pager
```

### Operations CLI

The installation includes `strata-console`, a branded CLI using the same control API and state as the web panel. It does not duplicate the engine or maintain a second state store:

```bash
strata-console status
strata-console models
strata-console optimize --profile balanced --context 200000
strata-console updates
strata-console traces --limit 20
strata-console evaluation run --model model-id --profile speed
strata-console connection
strata-console tunnel status
strata-console doctor --json
strata-console chat --model model-id --message "Hello"
```

Every command accepts `--json`, `--url` and `--token`. The token can be supplied with `STRATA_CONSOLE_TOKEN`; the CLI also reads the local runtime token without printing it. `strata-console serve` starts the server when systemd is not used.

### Python wheel

`pip install .` is supported for development and user-scoped environments. The wheel includes the panel, model config templates, schemas, parameter help and OpenAPI contract; installed runtime state defaults to `~/.local/state/strata-llm-console` unless `STRATA_CONSOLE_STATE_DIR` is set. The wheel does not install Strata or systemd units.

```bash
python3 -m pip install .
strata-console doctor --json
```

### Environment variables

- `STRATA_CONSOLE_HOST` — bind address; defaults to `127.0.0.1`.
- `STRATA_CONSOLE_PORT` — console port; defaults to `8090`.
- `STRATA_CONSOLE_TOKEN` — CLI token override; prefer the local mode-`0600` token file.
- `STRATA_CONSOLE_TOKEN_FILE` — explicit token path, useful for containers.
- `STRATA_CONSOLE_RATE_LIMIT` / `STRATA_CONSOLE_RATE_WINDOW` — gateway request budget; defaults to `120` requests per `60` seconds per source.
- `STRATA_CONSOLE_SERVICE` — systemd service name override.
- `TELEGRAM_STRATA_BOT_TOKEN` and `TELEGRAM_STRATA_ADMIN_IDS` — optional Telegram control, only through a mode-`0600` environment file.

## GitHub Packages / OCI image

Each version tag publishes an OCI package to:
```text
ghcr.io/monrroyag/strata-llm-console:latest
ghcr.io/monrroyag/strata-llm-console:<version>
```

Pull and run it on Linux with Docker or Podman:

```bash
docker pull ghcr.io/monrroyag/strata-llm-console:latest
docker run --rm --name strata-llm-console \
  -p 8090:8090 \
  -e STRATA_CONSOLE_HOST=0.0.0.0 \
  -v strata-console-data:/var/lib/strata-console \
  ghcr.io/monrroyag/strata-llm-console:latest
```

The image is non-root, has a health check, uses Python’s standard library only, and exposes the same panel and API. The image defaults to loopback; the example opts into container-network exposure explicitly. Mounting `/var/lib/strata-console` preserves the token and SQLite state across container replacement. When reachable from another host, keep the control token and remote authentication enabled. The native installer is the recommended mode when the console must control host systemd units and local Strata processes.

## Runtime persistence

Control-plane metadata is stored transactionally in `data/state.sqlite3` using SQLite WAL mode and full synchronous commits. On first startup, the store imports existing legacy JSON files and keeps atomic compatibility exports for older tools:

- catalog metadata;
- connection mode/CORS settings;
- tunnel lifecycle metadata;
- Telegram locale preferences.

The state database and compatibility files are local runtime artifacts, ignored by Git, protected with mode `0600`, and never contain model weights or API secrets. Jobs continue using their bounded SQLite queue; traces and performance history remain bounded append-only stores with clipped fields.

## Update monitoring

The console checks every 10 minutes, in the background, for:

- new commits in the official Strata engine repository;
- a newer Strata LLM Console release;
- the latest commit subject, date, version and comparison/changelog URL.

A visible header badge and the **System → Update** panel report pending engine or console updates. Telegram receives the same commit details. Updates are never applied silently: the operator reviews the changes and explicitly starts the engine or console update action.

## Runtime layout

- `catalog.json` — sanitized catalog template.
- `configs/` — path-neutral configuration templates.
- `data/` — runtime state, ignored by Git.
- `logs/` — runtime logs, ignored by Git.
- `models/`, `packs/`, `engine/` — local artifacts, ignored by Git.
- `docs/languages/` — documentation for every supported locale.

## Security and repository boundaries

This repository contains the console source and sanitized templates. It does not contain tokens, environment files, traces, logs, GGUF files, model packs, local engine binaries or machine-specific paths. Model removal is catalog-only: the console never deletes original model artifacts automatically.

Strata remains the execution engine. The console adds the operational layer around it without silently starting or mixing incompatible runtimes.
